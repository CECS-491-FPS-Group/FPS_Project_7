## Multiplayer audit

- Existing lobby has four name/status/latency slots and maximumPlayers=4. Server start still verifies every authenticated roster member.
- Ready RPC now derives identity from FishNet's sender. Fifth lobby connection is rejected instead of becoming an invisible participant.
- Existing local code/list registry has unique room ports, player count and capacity. It is same-computer discovery, not LAN/internet matchmaking (address remains 127.0.0.1).
- Terrain-ready, player ownership, currency, scoreboard and cleanup are keyed by connection or network identity, not hard-coded player IDs.
- Spawn candidates expanded from four to twelve. All retain terrain generation/readiness, exact collider raycast, CharacterController clearance and 4 m horizontal separation. No unsafe fallback. Initial availability failures retry once per second, logging once; caches clear on scene exit/disconnect.
- Respawn excludes its own existing player from separation. Gameplay players are explicitly despawned before FishNet global scene replacement.
- Player.prefab, DefaultPrefabObjects.asset, LobbyScene_v1 and RoundImplementation are unchanged. No new NetworkBehaviour or NetworkObject was introduced; pickup visuals are collider-free and snapshots are broadcasts.

## Controls and prototype behavior

- 1 Sidearm: 40 damage, 5 shots/sec, 30 rounds, semi-auto; 2 Rifle: 20 damage, 10 shots/sec, 30 rounds, automatic; 3 Shotgun: eight server pellets at 10 damage, 1 shot/sec, 8 rounds.
- R reload; switching cancels reload and preserves each magazine. Shot cooldown survives switching. Respawn refills all magazines. Clients request an index only, never damage/ammo/pellet values.
- Right mouse holds scope FOV; this is presentation only and does not grant a server accuracy modifier. Server generates all spread/bloom and pellet directions after validating the requested center aim.
- During GAME a server-chosen terrain-valid pickup appears every 10 seconds (up to four). Pickups expire after 30 seconds; effects last 20 seconds. Cyan shield, green 1.5x speed, yellow 1.5x jump height, red 2x damage. One effect per connection; replacement on collection. Death / leaving GAME / scene teardown clears effects. Server owns proximity collection, expiry, shield and damage. Client movement consumes only approved effect snapshots; this is not a movement anti-cheat implementation.
- F6 saves local movement JSON under Application.persistentDataPath/Replays; capture also saves when the player object is removed. No replay playback feature was integrated.
- Existing Tab scoreboard and phase/currency behavior remain unchanged. Audio plays on accepted shots; no audio listeners added.
